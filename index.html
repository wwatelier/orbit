Pipeline

Every piece across the production ladder. Click any row to update it.

How this board is worked out
  • Table. Every piece as rows — best for scanning many at once, and for bulk edits (tick rows, set stage or clear dates for all of them together).
  • Board. The same pieces grouped by Stage — best for seeing where work is stuck, at a glance.
  • Calendar. A day-by-day workload plan, not a posting schedule. Each piece sits on the day it should be worked on, spread within the team's daily capacity so no single day gets overloaded — the number by each date is how many pieces are due that day. Click a card to open it, or the date to see the full list. Best for planning the days ahead, or checking whether a day is about to get slammed.
  • What you see. Every active piece. Published, On Hold, Unselected and Rolled Over are moved to the collapsed sections underneath, so the board is only work that still needs doing.
  • Order. Soonest publish date first, so the top of the list is the most urgent.
  • Ready By is 14 days before the publish date, then pulled back off Sundays and any day marked off in Team Calendar. It is the production deadline, not the posting date.
  • On Track compares today against Ready By: 🟢 On track, 🟠 At risk within 3 days, 🔴 Behind once it has passed. A piece at Ready to Publish or Published is never Behind.
  • Ready buffer. The chips above show how many days of Ready-to-Publish content each client has ahead of today. Target is 7 days, and more is better. Amber means below target.
  • ⚠ Needs info means the piece is missing a publish date or a copy link.
  • Publish dates never move for a day off. Only the internal deadlines shift.

Next Batch

When each client's next batch proposal should start, go to the client, and be approved, so new content is ready before the current stock runs out.

How Next Batch is worked out
  • First post of the next batch. The earlier of two dates: four weeks after the current batch's first post, or the next posting day after the client's last scheduled post (when the stock runs out).
  • What counts as stock. Every post on the client's own feed that has a date and isn't On Hold or Unselected, including spin-offs and extra pieces the client asked for. Each row is one piece.
  • The steps. Start drafting 5 weeks before the first post, send it to the client 4 weeks before, client approval 3 weeks before, first piece ready 2 weeks before. The three proposal timings can be changed in the Settings tab.
  • The bell. Amber from the start date until the proposal is approved. Red when it should already be with the client, or approval is overdue. It clears once the status is Approved.
  • Status. Tap a status to save it for everyone. Sent and Approved record the date automatically. Every change shows in the Activity Log.

Publish Dates

Assign, oversee, and rearrange every client's publish schedule in one place.

How Publish Dates is worked out
  • What "Client" shows. Not just that client's own quota — everything that will actually appear on their feed, including a collab tracked under a different client's batch. Ice's own solo content and any piece she collabs on or posts from both show when you filter to Ice. Quota and batch counts are untouched — this only changes what you see.
  • Needs a date. Every undated piece, with a suggested date already worked out. Click Save on one, or Save all suggested for everything shown at once. Suggestions already respect posting days, collab days, and never double-book an account, so what's proposed is safe to save as-is.
  • Already scheduled. Everything with a date, soonest first. Click a row to open it, or the date to change it directly.
  • The Calendar. A different axis from Pipeline's — this one plots the actual Publish Date, not the workload deadline. Drag a card to a new day to reschedule it. Pick one client to see their regular posting days highlighted in yellow, and any recurring collab day marked.
  • Posting days. Each client is only suggested, or freely assigned, dates that fall on their own posting days, set in the Clients tab. Sunday is always off, for everyone, no exceptions.
  • Collab days. If a client has a recurring collab, set in the Clients tab, their own solo content skips that weekday automatically when suggesting dates — the day's already spoken for.
  • One account, one post a day. Checked by real account, not by which client's quota a piece happens to be tracked under. A collab homed under one client's batch still blocks the other account's own slot that day — nothing ever proposes two pieces landing on the same account, same day.
  • Overriding. Dragging or saving onto a day that breaks one of the two rules above still works — it just asks you to confirm first. Real life has delays; the system warns, it never blocks.
  • Auto-rearrange whole board. Re-dates every unpublished piece from scratch, for all clients at once — Melissa and Lynn too. It re-spaces each client across their own posting days and never double-books an account, but it does not use the fixed weekly pattern and saves straight away after a confirm. Use it for a full reset, or for clients not on the fixed pattern.
  • Reflow to fixed pattern. Ice, SRU and Dianna only. Lays them onto the 4-week posting grid (Week 1 starts Mon 28 Sep 2026; the Monday of each week shows W1–W4 on the calendar), pinning each collab to its slot and alternating formats. An empty slot stays empty, except an empty Ice + SRU day, which gets Ice's own post. Dianna's catch-up slots take only pieces from an older batch. Published and today/tomorrow posts stay put, and so does anything this run isn't moving. It shows a preview first — nothing is saved until you click Apply.
  • Posting pattern. Ice, SRU and Dianna follow one 4-week grid. Click Posting pattern to see each week, account by account; the current week is picked for you. It is drawn from the same grid Reflow, Push and the date checks use.
  • Posting style. Alternate formats keeps reels and carousels taking turns when auto-suggesting; Any format allows the same type back to back. Only affects what gets suggested, never what's already saved.
